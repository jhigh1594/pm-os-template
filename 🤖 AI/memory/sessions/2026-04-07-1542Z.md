## Summary
Investigated why /clear hook wasn't capturing sessions, discovered UserPromptSubmit doesn't fire for built-in CLI commands, redesigned capture mechanism using rolling-state.json + existing .specstory transcripts, deployed the fix, and committed to main.

## Focus
The session hook recovery system is now live. Rolling state writes intent + timestamp after each turn; session-start.sh recovers from rolling state when .specstory transcripts exist, enabling session recovery even after /clear.

## Decisions
- Switched from pre_clear_capture.py hook to rolling-state.json because UserPromptSubmit is architecturally unreliable for built-in commands
- Leveraged existing .specstory transcript files instead of trying to capture at CLI level
- Updated session-start.sh recovery block to check both session-intent.json AND .specstory transcript presence

## Open Questions
- session-intent.json intent field is never auto-populated — only set_intent.py (manual CLI tool) writes to it; rolling-state guards on non-empty intent, so the mechanism may not fire in practice

## Context Changes
Root cause was platform architecture (not a code bug) — shifted from debugging the hook to redesigning the capture mechanism around the platform's constraints.
