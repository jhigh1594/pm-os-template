# Mental Models Reference

Select 2-3 models per problem. Using all is noise.

## Decision Guide

```
  PROBLEM TYPE                    BEST MODELS
  ──────────────────────────────────────────────
  "Why isn't this working?"   →   Inversion, 5 Whys, Root Cause
  "What should we build?"     →   First Principles, JTBD, Inversion
  "Which option to pick?"     →   Second-Order, Opportunity Cost, Reversibility
  "Why do we keep failing?"   →   Feedback Loops, Survivorship Bias
  "How to prioritize?"        →   Pareto 80/20, Opportunity Cost, Eisenhower
  "Is this too complex?"      →   Occam's Razor, First Principles
  "What are we missing?"      →   Inversion, Circle of Competence
  "What will happen next?"    →   Second-Order, Probabilistic, Feedback Loops
```

## Models

### First Principles (Aristotle / Musk)
Strip away assumptions. What is fundamentally true? Build up from there.
```
  What we know for sure: [fact 1], [fact 2]
  What we assume: [assumption], [assumption]
  → Build reasoning ONLY from what we know for sure
```

### Inversion (Charlie Munger)
Instead of "how do I succeed?" ask "what guarantees failure?" — then avoid those things.
Often reveals blind spots faster than positive thinking.

### Second-Order Thinking
Every action has a consequence, and every consequence has a consequence.
```
  Action → First-order effect → Second-order effect → Third-order effect
  ──────────────────────────────────────────────────────────────────
  Lower prices → More customers → Higher support costs → Margin squeeze
```

### MECE Decomposition (McKinsey)
Mutually Exclusive, Collectively Exhaustive. Break problems into non-overlapping parts that cover everything.

### Probabilistic Thinking
Think in ranges, not point estimates. "60-70% chance" > "will happen."
Base rates > gut feelings.

### Opportunity Cost
Every choice is a trade against the next best alternative.
What are you NOT doing by doing this?

### Feedback Loops
Identify reinforcing (R) and balancing (B) loops.
```
  R: More features → More complexity → More bugs → More engineering time → Less features
  B: High price → Fewer customers → More attention per customer → Higher retention → Higher price justified
```

### Pareto 80/20 (Vilfredo Pareto)
80% of results come from 20% of inputs. Find the vital few vs trivial many.

### Occam's Razor
The simplest explanation that fits the facts is usually right.
If two models explain the same data, prefer the simpler one.

### Map vs Territory (Alfred Korzybski)
The model is not the thing. Don't confuse your understanding of the market with the actual market.

### Circle of Competence (Warren Buffett)
Know what you know and what you don't. Operate inside your circle; expand it deliberately.

### Survivorship Bias
We study the winners and ignore the dead. What would the failures teach us?

### Hanlon's Razor
Don't attribute to malice what can be explained by incompetence (or systems).

### Latticework (Charlie Munger)
The real power comes from connecting multiple models — the intersection creates insight that no single model provides.
