### Example: Weighted Matrices Reveal Answers Before Math

**Context**: User was deciding between three architecture approaches for a data pipeline.

**What happened**: While filling out the weighted criteria matrix, the user realized Option B was clearly better before finishing the calculations—the process of scoring forced clarity.

**Lesson**: The act of creating a decision matrix often surfaces the answer before the math is complete. The framework's value is in forcing explicit criteria and scores, not in the final number.

**How to apply**: When facilitating weighted matrix decisions, pause after scoring to ask "Is the answer already clear?" before calculating totals.

---

### Example: Two-Way Doors Get Over-Analyzed

**Context**: User spent two weeks analyzing whether to A/B test a button color change.

**What happened**: The analysis time exceeded the engineering time to just ship the test. The feature was reversible and low-stakes.

**Lesson**: Two-way door decisions often attract analysis appropriate for one-way doors. The 70% rule exists specifically to prevent this.

**How to apply**: When a user brings a reversible decision, explicitly call out "this is a two-way door" and apply the 70% rule before diving into analysis.
